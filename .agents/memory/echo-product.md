---
name: ECHO product direction
description: User-approved product identity, privacy rules, accessibility preference, and AI boundaries.
---

ECHO is a private fictional-character social universe experienced as Nela Paez's own social account, not an administration dashboard. Mar Mulligan and Noah Hayes are distinct characters. Manual character switching must remain unobtrusive.

**Why:** The user said she wants to control Nela as herself, posting and participating from her profile.

**How to apply:** Keep primary navigation focused on feed, stories, profiles and conversations. Put character control in secondary settings.

New inboxes must start empty. An available character is a contact, not a conversation; selecting one without sending anything must not add an empty thread.

**Why:** The user explicitly requested that DMs appear from interaction, not automatically list every character. She also required existing and migrated conversations to remain intact.

**How to apply:** Seed no messages for new universes. Derive inbox rows from persisted message history, including already-stored illustrative/seed messages and archived participants; do not purge that history to produce a visually empty inbox. Keep a clear searchable way to start a new conversation.

Every social account, including Nela/the user's own profile, must be manually editable. Personal characters and official bands/places are equally usable posting identities within each owner's isolated universe.

**Why:** The user explicitly said “ALL accounts, including Nela/user’s own account, must be manually editable” and wants to switch to any character or official account, act manually, then switch back.

**How to apply:** Do not give account management privileges based on the active character. Owner controls belong to the signed-in universe owner; changing a fictional profile must not change their authentication account.

Each person's universe belongs to their signed-in account. Posts, conversations and private images must stay owner-scoped on the server. Read legacy browser data only to migrate it, and retain it until the cloud copy succeeds.

**Why:** The user asked for a private network with secure sign-in and access to the same universe across devices, without losing existing content.

**How to apply:** Scope every state and media read/write to the authenticated owner; never treat browser storage or a public object URL as the privacy boundary.

The approved visual direction is black/charcoal dark mode, soft contrast, subtle muted pink, harmonious rounded controls and friendly icons, with an iPhone-first layout. The user stated that bright screens hurt her eyes.

**Why:** The user explicitly approved this appearance and asked for comfortable dark screens.

**How to apply:** Preserve dark mode throughout secondary screens, dialogs and creation flows, not just the feed.

ECHO currently uses simulated character activity without API keys. Later phases may connect each character to a Kindroid Kin ID/API and a visual-generation provider with persistent character identity references.

**Why:** The user requested a usable first prototype without requiring credentials, while preserving a path to autonomous social activity.

**How to apply:** Keep provider contracts separate from UI and distinguish simulated activity from live AI.
